# 开源工具报错：先核对上游

首次发现本地实测失败或异常时，暂停自行修改源码、请求参数、依赖或配置的修复尝试。先保存现有错误与最小上下文；允许只读定位实际调用路径、版本及日志，不先扩成反复重试或本地改造。

## 必须先完成的核对

1. **实际运行的是什么**：确认可执行文件/模块/容器路径、包名、版本、安装渠道和锁文件；源码安装记录 commit，镜像记录 tag/digest。检查缓存、全局/局部安装、多入口是否使调用仍落到旧副本。不能只凭安装命令中的 `latest` 判断当前版本。
2. **最新版本修了什么**：访问官方包仓库、Release/Changelog，核对当前渠道最新稳定版及适用平台。区分稳定版、预发布、Git 主线、已合并但未发布的提交；阅读与当前症状相符的修复记录，核对修复是否真正进入下载制品。相同版本号不保证源码与构建产物一致。
3. **社区是否已经遇到**：用项目名、版本和脱敏报错，检索对应仓库的开放及关闭 Issues、PR、Discussions；中英文按项目情况补查。打开相似记录及关键评论，核对环境、日期、合并状态、维护者回复和复验结果。Closed 不等于修复，Merged 不等于已发布，单测通过不等于本机调用成功。

## 核对后的处理

- 用简短结论给出当前/最新版本、相似记录链接、修复所在版本或 commit，以及是否适用于本次故障。
- 已有适用修复：优先在可回滚的隔离副本验证正式发布版或固定 commit，保留来源和差异，再按既有授权决定是否应用。核对版本不等于自动升级，更不授权改认证、网络、付费服务或其他入口。
- 未找到适用修复、或上游方案在本机仍失败：记录检索范围与证据，再进入有依据的本地诊断；不要把搜索未命中写成“社区没有此问题”。
- 上游不可访问或版本信息不明：明确标为未核实，继续可做的只读取证；不能当作已完成前置核对后直接修补。用户明确要求离线或跳过时，以该指令为准并说明缺失证据。
- 验证必须覆盖用户实际工具、入口和路由。区分故障识别改善、可用性恢复、结果质量；验证码、空结果、HTTP 成功和相关性不能互相代替。

检索只发送公开项目标识与脱敏症状，不上传本地路径、密钥或私有业务内容。发 Issue、评论、PR 等对外写入另按用户授权执行。本技能不要求自动升级、常驻监控或新建审批流程；已有相同版本和症状的本次核对证据可复用。
